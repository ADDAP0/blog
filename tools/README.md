# 写作后台

一个跑在本机的写作工具，用来发文章和传图片，省得每次都手动改文件。

## 怎么打开

**双击桌面上的「写作后台」图标**就行。

它会自己把服务起起来，然后用一个干净的窗口打开（没有地址栏、没有标签页，看着就像个独立软件）。同一个图标再点一次不会重复启动，只会把窗口叫到前面来。

第一次用如果桌面上没有图标，双击 `tools\启动后台.vbs` 也可以，或者运行这一行给它建一个：

```powershell
powershell -ExecutionPolicy Bypass -File tools\安装快捷方式.ps1
```

## 装进系统（PWA）

后台支持被「安装」成系统应用。装好之后：

- 出现在**开始菜单**里，可以直接搜索到
- 任务栏是**独立图标**，不混在浏览器里
- 独立窗口、独立分组

**怎么装**：打开后台，如果顶栏出现蓝色的 **「⬇ 安装到系统」** 按钮，点它就完事。

按钮没出现的话，用浏览器自带的入口也行：

- **Edge**：地址栏右侧「⋯」→ 应用 → 将此站点作为应用安装
- **Chrome**：地址栏右侧的安装图标，或菜单 → 投放、保存和分享 → 安装页面为应用

### 装了它就得配一件事：开机自启

PWA 从开始菜单启动时，**后台服务必须已经在跑** —— 网页没有办法自己启动本地程序。
所以想让开始菜单那个图标随时能用，就得让服务常驻：

```powershell
# 开启
powershell -ExecutionPolicy Bypass -File tools\设置开机自启.ps1

# 不想要了就关掉
powershell -ExecutionPolicy Bypass -File tools\设置开机自启.ps1 -Remove

# 看看现在是开是关
powershell -ExecutionPolicy Bypass -File tools\设置开机自启.ps1 -Status
```

它做的事很简单：在「启动」文件夹里放一个快捷方式，开机时静默把服务拉起来。

代价是常驻一个 Node 进程（几十 MB 内存）。不想常驻就别开，
继续用桌面图标 —— 点一下启动也就两秒。

## 怎么关闭

窗口右上角有个 **电源按钮**，点它服务就停了。

（因为启动时不显示命令行窗口，只能从这里关，不然得去任务管理器里找 node 进程。）

关掉之后那个窗口就打不开页面了，下次点桌面图标重新启动即可。

## 排错：想看到日志怎么办

桌面快捷方式是把命令行窗口藏起来的，所以出错时看不到提示。这种时候用 `启动后台.bat`，
它会保留一个黑色窗口，服务的日志都打在里面。

## 有什么

| 页签 | 干什么 |
|---|---|
| **写文章** | 填标题、分类、标签、摘要，左边写 Markdown、右边实时预览。点保存就生成 `posts/*.md`，并自动重建站点数据 |
| **文章列表** | 看所有文章，点「编辑」载入表单，点「删除」移入回收站 |
| **相册** | 拖图片进来就加进相册，填好标题和描述后保存。相册决定首页大图卡轮播什么，也决定「照片」计数 |
| **音乐** | 拖音频（mp3 / m4a / ogg / wav / flac…）或歌词（lrc）进来。音频会自动加成一条，再选歌词和封面就行。这里决定首页音乐卡和播放列表页放什么 |
| **图片库** | 对应 `images/` 目录。上传、复制 Markdown 引用、删除（进回收站） |
| **友链** | 维护「链接 → 友情链接」页面。头像可以填外链，也可以填 `images/xxx.jpg` |
| **回收站** | 删掉的东西都在这，可以恢复，也可以彻底删除 |
| **发布** | 提交和推送，见下面「同步」一节 |

## 同步：断网也不会丢东西

后台**把「提交」和「推送」当成两件事**，这是故意的：

```
① 本地改动  →  ② 已提交未推送  →  ③ GitHub
   改文件        写进本地 git        联网上传
```

- **提交**只写你本机的 git 历史，**不需要网络**，几乎一定成功
- **推送**才需要联网，也才可能失败

所以断网时你先点「只提交到本地」，改动就稳稳落在本地 git 里了。
等网络好了再点「只推送」——**不会丢任何东西**。

### 打开后台会自动核对云端

每次打开后台都会真的连一次 GitHub，把本地和云端比一遍：

| 情况 | 后台怎么做 |
|---|---|
| 两边一致 | 显示「已核对：本地和云端完全一致」 |
| 本地干净、云端有更新 | **自动拉下来**，保持两边一致 |
| 本地有未提交改动 | 不自动动，提示你先提交或放弃 |
| 本地有未推送提交 | 不自动动，提示你先推送 |
| 两边都改过（分叉） | 红色警告，让你自己决定 |
| **连不上 GitHub** | 明说「这次没核对上」，并注明下面显示的云端记录是旧的 |

最后一条很重要：**连不上的时候绝不会假装"已一致"**。
很多工具会在这种时候拿缓存糊弄你，结果你以为同步了其实没有。

### 用云端覆盖本地

如果有需要（比如本地改乱了、想以云端为准），可以用这个功能。它按这个顺序来：

1. **先确认连得上** GitHub —— 连不上就直接退出，一个字节都不碰
2. **建备份分支** `backup/时间戳`，存下当前状态
3. **把未提交的改动存进 stash**
4. 才执行覆盖

所以即使后悔了也有得捞。用完不需要的备份分支可以删掉。

顶栏那个小圆点随时告诉你处在哪一步：

| 显示 | 意思 |
|---|---|
| 🟢 已与 GitHub 同步 | 本地和云端一致，没活儿 |
| 🟡 N 处改动没提交 | 改了文件但还没提交 |
| 🔵 N 个提交没推送 | 提交了，但还没传上去 |
| 🔴 读不到 git 状态 | git 出问题了 |

点它可以直接跳到「发布」页。

**推送失败时**，后台会明确告诉你「已提交到本地（xxxxx），改动没丢」，
而不是只丢一句"失败"让你干着急。

## 回收站

删文章、删图片**不会真的从磁盘消失**，而是挪进 `tools/.trash/`，
在「回收站」页签里可以：

- **恢复** —— 放回原来的位置，并自动重建站点数据
- **彻底删除** —— 这才是真的删掉，删前会确认

`tools/.trash/` 已经写进 `.gitignore`，不会进仓库。

## 放弃未提交的改动

「发布」页有个「放弃未提交的改动」按钮，用来把**已跟踪文件**恢复到上次提交的样子。

用途：本地改乱了想重来。注意两点：

- 已经**提交过**的东西不受影响（想撤销提交得用 `git reset`）
- **新上传但还没提交**的文件不会被删除

## 几个细节

- **写文章页的「上传并插入图片」** 会在光标处插入 Markdown 引用，路径自动写成 `../images/xxx.jpg`
  —— 因为文章是在 `pages/post.html` 里渲染的，只有写成 `../` 才能正确显示。
- **上传重名不会覆盖**，会自动变成 `xxx-1.jpg`、`xxx-2.jpg`。
- **预览用的是站点自己的渲染器**（`js/markdown.js`），所以后台看到的效果和线上一致。
- **文件按扩展名自动分流**：图片进 `images/`，音频和歌词进 `music/`，不用你选目录。
- **音乐页签里每条都能试听**，改完点「保存播放列表」才生效。

## 从首页怎么进播放列表

首页那张音乐卡，点封面、曲名这些地方就会进 `pages/music.html`；
点播放键、进度条这些控件不会跳转（避免误触）。

进去之后能接着刚才的进度放——自动播放如果被浏览器拦了，点一下播放键就行。

## 安全

服务只监听 `127.0.0.1`，局域网和公网都访问不到。

它能读写你的项目文件、执行 `git`，所以**别改端口去对外暴露**。
