# 写作后台

一个跑在本机的写作工具，用来发文章和传图片，省得每次都手动改文件。

## 怎么用

双击 **`启动后台.bat`**，浏览器会自动打开 <http://127.0.0.1:4321>。

关掉那个黑色命令行窗口就是停止（或者在里面按 `Ctrl+C`）。

也可以手动起：

```bash
node tools/server.js
```

## 有什么

| 页签 | 干什么 |
|---|---|
| **写文章** | 填标题、分类、标签、摘要，左边写 Markdown、右边实时预览。点保存就生成 `posts/*.md`，并自动重建站点数据 |
| **文章列表** | 看所有文章，点「编辑」载入表单，点「删除」移入回收站 |
| **相册** | 拖图片进来就加进相册，填好标题和描述后保存。相册决定首页大图卡轮播什么，也决定「照片」计数 |
| **音乐** | 拖音频（mp3 / m4a / ogg / wav / flac…）或歌词（lrc）进来。音频会自动加成一条，再选歌词和封面就行。这里决定首页音乐卡和播放列表页放什么 |
| **图片库** | 对应 `images/` 目录。上传、复制 Markdown 引用、删除（进回收站） |
| **友链** | 维护「链接 → 友情链接」页面。头像可以填外链，也可以填 `images/xxx.jpg` |
| **回收站** | 删掉的东西都在这，可以恢复，也可以彻底删除 |
| **发布** | 提交和推送，见下面「同步」一节 |

## 同步：断网也不会丢东西

后台**把「提交」和「推送」当成两件事**，这是故意的：

```
① 本地改动  →  ② 已提交未推送  →  ③ GitHub
   改文件        写进本地 git        联网上传
```

- **提交**只写你本机的 git 历史，**不需要网络**，几乎一定成功
- **推送**才需要联网，也才可能失败

所以断网时你先点「只提交到本地」，改动就稳稳落在本地 git 里了。
等网络好了再点「只推送」——**不会丢任何东西**。

顶栏那个小圆点随时告诉你处在哪一步：

| 显示 | 意思 |
|---|---|
| 🟢 已与 GitHub 同步 | 本地和云端一致，没活儿 |
| 🟡 N 处改动没提交 | 改了文件但还没提交 |
| 🔵 N 个提交没推送 | 提交了，但还没传上去 |
| 🔴 读不到 git 状态 | git 出问题了 |

点它可以直接跳到「发布」页。

**推送失败时**，后台会明确告诉你「已提交到本地（xxxxx），改动没丢」，
而不是只丢一句"失败"让你干着急。

## 回收站

删文章、删图片**不会真的从磁盘消失**，而是挪进 `tools/.trash/`，
在「回收站」页签里可以：

- **恢复** —— 放回原来的位置，并自动重建站点数据
- **彻底删除** —— 这才是真的删掉，删前会确认

`tools/.trash/` 已经写进 `.gitignore`，不会进仓库。

## 放弃未提交的改动

「发布」页有个「放弃未提交的改动」按钮，用来把**已跟踪文件**恢复到上次提交的样子。

用途：本地改乱了想重来。注意两点：

- 已经**提交过**的东西不受影响（想撤销提交得用 `git reset`）
- **新上传但还没提交**的文件不会被删除

## 几个细节

- **写文章页的「上传并插入图片」** 会在光标处插入 Markdown 引用，路径自动写成 `../images/xxx.jpg`
  —— 因为文章是在 `pages/post.html` 里渲染的，只有写成 `../` 才能正确显示。
- **上传重名不会覆盖**，会自动变成 `xxx-1.jpg`、`xxx-2.jpg`。
- **预览用的是站点自己的渲染器**（`js/markdown.js`），所以后台看到的效果和线上一致。
- **文件按扩展名自动分流**：图片进 `images/`，音频和歌词进 `music/`，不用你选目录。
- **音乐页签里每条都能试听**，改完点「保存播放列表」才生效。

## 从首页怎么进播放列表

首页那张音乐卡，点封面、曲名这些地方就会进 `pages/music.html`；
点播放键、进度条这些控件不会跳转（避免误触）。

进去之后能接着刚才的进度放——自动播放如果被浏览器拦了，点一下播放键就行。

## 安全

服务只监听 `127.0.0.1`，局域网和公网都访问不到。

它能读写你的项目文件、执行 `git`，所以**别改端口去对外暴露**。
